45 // ---- Stuck-element sizing refinement --------------------------------
46 // Trigger threshold: fire when the last iteration's improvement is small compared
47 // with the distance the max energy still has to cover, i.e. refine when
48 // (prev_max - max) <= stall_eps * (max - target).
49 // Equivalently: refine unless the mesh is on course to reach the target within
50 // about 1/stall_eps more iterations. 0 => only when it does not improve at all.
51 //
52 // The denominator is the remaining distance, not prev_max, and that is the whole
53 // point. Measured against prev_max, a mesh grinding down at a steady 1.3% per
54 // iteration toward a target far below clears a 1% bar every single iteration and so
55 // never looks stalled -- even though at that rate it needs on the order of a hundred
56 // more iterations and the operations have in fact deadlocked. The escape hatch then
57 // never fires, which is exactly the regime it exists for.
58 double stuck_refine_stall_eps = 0.1;
59 // Cooldown: after a refinement, skip this many improvement iterations before
60 // refining again, so the operations get full passes to act on the new sizing
61 // field before more refinement is added. 0 => may refine every iteration.
62 //
63 // 0 by default: measured over 468 triwild20k models, a cooldown of 1 costs ~13% wall
64 // time for exactly the same mesh sizes (identical median and p90 vertex counts). The
65 // idea that the operations need an idle iteration to act on the new field does not
66 // survive contact with the data -- the trigger already declines to fire while the mesh
67 // is converging, so a separate cooldown only delays the next escape.
68 int stuck_refine_cooldown = 0;
69 // Number of worst cells (by energy) whose neighborhoods are refined.
70 int stuck_refine_num_worst = 0;
71 // Graph rings around each worst cell's vertices included in the refinement.
72 int stuck_refine_rings = 0;
73 // Multiplicative reduction of m_sizing_scalar per refinement (0.5 => /2).
74 double stuck_refine_factor = 0.5;
75 // Lower bound on m_sizing_scalar. Much smaller than the old l_min/l floor;
76 // still far above the position-rounding scale so it stays numerically safe.
77 double stuck_refine_min_scalar = 1e-3;
78 // Gradation cap for the monotone sizing smoothing: neighboring sizings may
79 // differ by at most this factor. The smoothing only ever *lowers* sizings
80 // (spreads refinement outward), never raises the refined values, avoiding
81 // sharp resolution jumps that make operations ill-conditioned.
82 double stuck_refine_gradation = 2.0;
83 // Force-split: when the max energy stalls, split each worst cell's longest edge
84 // once, bypassing the split length gate. This unsticks a sliver whose edges are
85 // too short to be split-eligible, WITHOUT touching the sizing field (which the
86 // *factor ratchet above still drives). Adds at most one split per worst cell per
87 // stall, so it does not bloat the element count.
88 //
89 // This deliberately applies to EVERY worst cell, including one already at its target
90 // size. There used to be a stuck_refine_force_split_oversized_only gate that skipped
91 // those, on the argument that AMIPS is scale invariant so subdividing a badly shaped
92 // cell yields two badly shaped cells. The argument is sound about the cell itself and
93 // wrong about the outcome: force-splitting it also refines its NEIGHBOURHOOD, and that
94 // is what breaks a deadlocked configuration open. On Thingi10K 46024 -- the one model of
95 // 10,000 in the sweep that finished above stop_energy -- the gate refused ~2000 tets on
96 // every stall, the max energy froze at iteration 3 and stayed identical to 15 significant
97 // figures for the remaining 77 iterations (4.6 h). Without the gate the same model
98 // converges to 9.98 in 14 iterations and 11 minutes.
99 bool stuck_refine_force_split = true;
100
101
102 // ---- Skip good regions ----------------------------------------------
103 // Only smooth vertices incident to a cell whose energy is >=
104 // skip_good_regions_margin * stop_energy. Smoothing a vertex surrounded by
105 // good cells does nothing, so skipping it is free (14-16x faster smooth
106 // passes). Only smoothing is gated: gating the topology/sizing ops
107 // (split/collapse/swap) starves the optimizer and blows up the element
108 // count, so those always run over the whole mesh.
