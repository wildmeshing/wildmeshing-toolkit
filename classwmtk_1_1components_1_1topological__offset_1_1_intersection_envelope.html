Detailed Description

Containment-only composites over per-tag boundary envelopes, in both dimensions.

Both classes override exactly the four virtual queries of wmtk::Envelope – is_outside(triangle3), is_outside(point3), is_outside(segment2) and is_outside(point2) – which are the only calls the containment paths make.

Both construct their base in sampled mode, use_exact = false: the value the base's default constructor gave them before the default became exact. The flag is inert here – a composite is never init()ed and nothing reads use_exact off one – so this only keeps the change of default from changing anything.

A composite must never reach a caller of the non-virtual Envelope queries: nearest_point, nearest_point_feature, squared_distance, or the edge/2D is_outside overloads. Those bind statically to the base subobject, whose BVH was never built, and dereference null. Such callers are fed by smoothing_energy_envelope(), and that hook returns a single real member envelope by contract – the most-violated one for a junction vertex – never a composite. Inside means inside every member: the tube intersection. This is what pins a junction simplex to the junction, within eps of each boundary it lies on, and what holds a wire or isolated point of the input complex in place, since those only arise where two or more selected tags meet.

Four containment queries are VIRTUAL – the 3D triangle, the 3D point, the 2D segment and the 2D point – so a containment-only composite over several envelopes can answer them. They are exactly what the 3D and the 2D containment paths ask. The 3D segment query is not virtual. See the composites in components/topological_offset/.../TagEnvelopes.hpp, and the invariant stated there: a composite must never reach the NON-virtual queries, whose BVH it does not have.
