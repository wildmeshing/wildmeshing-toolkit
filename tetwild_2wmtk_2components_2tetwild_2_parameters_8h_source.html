33 // ---- Stuck-element sizing refinement --------------------------------
34 // Trigger threshold: fire when the last iteration's improvement is small compared
35 // with the distance the max energy still has to cover, i.e. refine when
36 // (prev_max - max) <= stall_eps * (max - target).
37 // Equivalently: refine unless the mesh is on course to reach the target within
38 // about 1/stall_eps more iterations. 0 => only when it does not improve at all.
39 //
40 // The denominator is the remaining distance, not prev_max, and that is the whole
41 // point. Measured against prev_max, a mesh grinding down at a steady 1.3% per
42 // iteration toward a target far below clears a 1% bar every single iteration and so
43 // never looks stalled -- even though at that rate it needs on the order of a hundred
44 // more iterations and the operations have in fact deadlocked. The escape hatch then
45 // never fires, which is exactly the regime it exists for.
46 double stuck_refine_stall_eps = 0.1;
47 // Cooldown: after a refinement, skip this many improvement iterations before
48 // refining again, so the operations get full passes to act on the new sizing
49 // field before more refinement is added. 0 => may refine every iteration.
50 //
51 // 0 by default: measured over 468 triwild20k models, a cooldown of 1 costs ~13% wall
52 // time for exactly the same mesh sizes (identical median and p90 vertex counts). The
53 // idea that the operations need an idle iteration to act on the new field does not
54 // survive contact with the data -- the trigger already declines to fire while the mesh
55 // is converging, so a separate cooldown only delays the next escape.
