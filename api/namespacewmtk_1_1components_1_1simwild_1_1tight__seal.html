Detailed Description

Helpers of the geometric tight seal, whose operation is SimWildMeshTri::tight_seal_geom (AnnotationsTri.cpp) and SimWildMesh::tight_seal_geom (AnnotationsTet.cpp). The helpers below need no mesh; those that do are private members of the two mesh classes, defined in TightSealGeom.cpp. The fill is tight_seal::PairFill (TightSealPairFill.hpp).

The fill of the geometric tight seal (tight seal v2 note, section 4.2, https://hackmd.io/@Spenbert02/HkX3vAvaGg). It reaches the mesh only through the hooks of PairFill::Mesh, so the same code fills triangles (N = 3) and tets (N = 4).

Each component to fill (C_i in the note) has K functions, one per color it borders: the distances to those colors, taken at the vertices the mesh had before the fill and linear in each of the component's cells then (its original cells). The fill splits edges, nothing else, until the corners of every cell share a function smallest there; by linearity that function is smallest on the whole cell, and labels it.

Vertices. Each vertex v holds the values d_k(v). The note keeps a list E(v) of pairs (k, l) counted as exactly equal at v, whatever their stored values; here a pair is in E(v) exactly when its stored values are equal, so every comparison is between plain values and is transitive. A vertex the mesh had keeps its values (E(v): the pairs with equal input values). A vertex x the fill makes on the edge (a, b), at fraction s from a, takes d_k(x) = (1 - s) d_k(a) + s d_k(b) for every k, and then ties, in classes whose members all take the class's least value:

  • the pair (i, j) it was made for (in its component only);
  • every pair tied at both a and b (with equal inputs the interpolation gives equal values, so such a pair is only tied explicitly once another tie moved one of its values);
  • every pair whose values at x lie strictly on one side while a and b both lie on the other side or on the level (closed side): x must stay on its edge's side of every level set, as the note's remark asks of each split;
  • and, by the classes, every pair tied through others: d_k = d_l and d_l = d_m give d_k = d_m. Each tie can move values, so the last two are checked again until nothing changes. The note does not close E(x) this way. Without it, a vertex x at a triple point, made for (i, j) on an edge whose ends tie (i, m), gets (i, j) and (i, m) but not (j, m); rounding then puts d_j - d_m a few ulps off 0, the edges from x cross that level set, and their splits pile up at x without ending the cells there. In exact arithmetic neither the closure nor the side check ever ties a pair the note does not; they are counted (Stats::n_closed). A vertex's label set: the functions with the least value there.

Cells. A cell is finalized if its corners' label sets share a function, which labels it (the smallest if several). An original cell is finalized when all its children are.

The fill, for each original cell t in turn, unless it is finalized. A function is dominated in t if another is strictly smaller at all of t's corners; it is then smallest nowhere in t, and is left out. For each pair (i, j) of the others in turn, each vertex of t's children has a sign, that of d_i - d_j (0 for a tie). A queue starts with t's unfinalized children. A cell popped is skipped if it is gone (split since it was queued), finalized, or has no edge from a + vertex to a - one; otherwise its first such edge (a, b), corners sorted by id, is split where d_i - d_j vanishes, s = δ(a) / (δ(a) - δ(b)) with δ = d_i - d_j. Each cell the split makes, in t or not: takes its parent's label if its parent was finalized; else its own, if it is finalized; else is queued if it lies in t; else waits for its own original cell.

Each split removes one edge across the pair's level set and makes none (every new edge ends at the new vertex, a tie for the pair), so each pair ends. Every vertex of t lies on the closed side its edge's ends share of each level set, so a pair done stays done, and a function dominated at t's corners stays at least its dominator everywhere in t. Once t's last pair is done, no child of t has an edge across a level set of t's other functions: "d_k <= d_l at every corner" is then a total order on them in each child (comparisons at a vertex are transitive), and its least function is smallest at every corner, dominated functions included. So each child is finalized. A cell left unfinalized (only by a refused split) is labelled by the function smallest at its centroid, and counted (Stats::n_fallback).

Where a 1-Lipschitz f reaches level along the segment [a, b], coming from a, which is below the level if from_below (f(a) < level), else above it (f(a) > level).

Sphere traced from a, each step |f - level| + step_floor (at least step_floor, so the trace ends; no step goes more than step_floor past the level), until f is at the level or past it; the last step is then bisected to the level. Nothing if f(a) is not on the side from_below gives, or if f stays on that side up to b.
