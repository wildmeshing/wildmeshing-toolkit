25 // Eleven bytes. The values are tiny -- a flag, a bbox side in [-1, 5], a class in {0, 1}, an
26 // orientation count that is +-1 or 0 almost everywhere, a 64-bit input set -- but as int the
27 // struct was 12 bytes, and the 3D meshes carry four of these per tet slot (the 2D ones three
28 // per triangle slot) in storage preallocated several times over: on the largest tetwild
29 // inputs that alone was most of a gigabyte. The class and the orientation share a byte as
30 // bitfields; both are int8_t so every compiler packs them together. The input set took it
31 // from 3 to 5 bytes, 8 more per tet slot: on Thingi10K 46024, the largest tetwild input of
32 // the challenging set (156k tets after insertion, two iterations), peak RSS went from 1006
33 // to 1017 MB (+1.1%), the simplification's per-face input id included. 64 bits rather than 16
34 // so that simwild can give every label its own bit -- each tet tag's region as well as each
35 // face tag -- and hold every surface face to its own labels' envelopes: segmented images
36 // carry more than 16 labels. That is 6 bytes more per face record: on the same
37 // 46024, one input, serial, peak RSS 1001 MB on main (3 bytes) and 1007 MB here (11 bytes).
