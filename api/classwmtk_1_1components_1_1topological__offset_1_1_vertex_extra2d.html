Detailed Description

Per-vertex data the shared 2D optimizer knows nothing about.

Position, rounding, bbox membership, sizing and partition all live on wmtk::TriOptimizerMesh::VertexAttributes. The three flags here say which tracked surface a vertex belongs to; the base's m_is_on_surface is their union, and they are not exclusive – a vertex where the offset boundary meets another region's boundary carries both.

◆ label

int wmtk::components::topological_offset::VertexExtra2d::label = 0

The construction label: 1 on the input complex, 2 on a band triangle off it, 0 elsewhere. The construction writes it; the optimization keeps it at every split's new vertex and every collapse's survivor and link (TopoOffsetTriMesh::carried_vertex_label()), from what 2D's operations carry. 3D keeps its labels by its carried edge labels (close_labels()); 2D's edge label (EdgeExtra2d::label) is not carried, and is read only before the optimization.

◆ m_born_epoch

uint32_t wmtk::components::topological_offset::VertexExtra2d::m_born_epoch = 0

Which split pass created this vertex, from wmtk::TriOptimizerMesh::m_op_epoch; 0 means not created by an optimization split. Read only by the needle diagnostics' per-vertex lines. Assigned at each split, never OR'd – a recycled slot carries a dead vertex's epoch.

◆ m_boundary_labels

LabelIds wmtk::components::topological_offset::VertexExtra2d::m_boundary_labels

Which tag boundaries this vertex lies on – one label per input tag, ambient included (TopoOffsetTriMesh::m_tag_label). See TopoOffsetTriMesh::m_tag_envelopes for what the labels dispatch to.

Seeded in init_surfaces_and_boundaries() from the input partition, then propagated by the operations: a split's new vertex takes the intersection of its endpoints' (it lies on a boundary only if the whole edge did), a collapse's survivor the union (it carries both vertices' geometry). Until 2026-11 a 64-bit mask, one bit per tag, which refused more than 62 input tags.

◆ m_corr_input_vid

int64_t wmtk::components::topological_offset::VertexExtra2d::m_corr_input_vid = -1

The input-complex vertex this offset vertex was split off from by marching_tris(): the marched edge's endpoint on the complex. -1 for every vertex the march did not make. Written into the output .msh by save_offset_correspondence; not maintained by the optimization. The 3D twin is VertexExtra::m_corr_input_vid.

◆ offset

int wmtk::components::topological_offset::VertexExtra2d::offset = -1

The entry of Parameters::offsets whose input complex this vertex is on (label 1), set by label_input_complex(); -1 on every other vertex, a split's new vertex included. As VertexExtra::offset in 3D.

◆ point_inputs

LabelIds wmtk::components::topological_offset::VertexExtra2d::point_inputs

The labels of the input points on this vertex, bit j for the base's m_point_names[j]: set at load (init_from_image()) and carried by the construction, which only splits, a new vertex starting from none (marching_split_edge_before(), split_face_before()), until hold_curves_and_points() anchors the points and clears it: from there on the anchors carry them, through the operations, which do not carry this. As VertexExtra::point_inputs in 3D. A mesh not held (an empty input complex) writes its point block from this (collect_loaded_curves_and_points()).
