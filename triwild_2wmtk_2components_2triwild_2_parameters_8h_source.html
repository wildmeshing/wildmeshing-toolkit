108 // ---- Stuck-element sizing refinement --------------------------------
109 // Same names, defaults and meaning as tetwild/simwild -- see the specs.
110 //
111 // Trigger threshold: fire when the last iteration's improvement is small compared
112 // with the distance the max energy still has to cover, i.e. refine when
113 // (prev_max - max) <= stall_eps * (max - stop_energy).
114 // Equivalently: refine unless the mesh is on course to reach the target within
115 // about 1/stall_eps more iterations. 0 => only when it does not improve at all.
116 //
117 // The denominator is the remaining distance, not prev_max, and that is the whole
118 // point. Measured against prev_max, a mesh grinding down at a steady 1.3% per
119 // iteration from 27 toward a target of 5 clears a 1% bar every single iteration and
120 // so never looks stalled -- even though at that rate it needs ~130 more iterations
121 // and the operations have in fact deadlocked. The escape hatch then never fires,
122 // which is exactly the regime it exists for.
123 double stuck_refine_stall_eps = 0.1;
124 // Cooldown: after a refinement, skip this many improvement iterations before
125 // refining again, so the operations get full passes to act on the new sizing
126 // field before more refinement is added. 0 => may refine every iteration.
127 //
128 // 0 by default: measured over 468 triwild20k models, a cooldown of 1 costs ~13% wall
129 // time for exactly the same mesh sizes (identical median and p90 vertex counts). The
130 // idea that the operations need an idle iteration to act on the new field does not
131 // survive contact with the data -- the trigger already declines to fire while the mesh
132 // is converging, so a separate cooldown only delays the next escape.
133 int stuck_refine_cooldown = 0;
134 // Number of worst triangles (by energy) whose neighborhoods are refined.
135 // 0 => every triangle above the filter energy, max(max_energy / 100, stop_energy).
136 // Beware in 2D: the AMIPS2D energy of an equilateral triangle is 2, so a stop_energy
137 // close to that makes the filter catch nearly the whole mesh, and with force_split on
138 // that means thousands of gate-bypassing splits per stall.

155 // When a split's rounded (double) midpoint would invert an incident triangle, the

161 // ---- Skip good regions ----------------------------------------------
162 // Only smooth vertices incident to a triangle whose energy is >=
163 // skip_good_regions_margin * stop_energy. Smoothing a vertex surrounded by
164 // good triangles does nothing, so skipping it is free. Only smoothing is
165 // gated: gating the topology/sizing ops (split/collapse/swap) starves the
166 // optimizer and blows up the element count, so those always run over the
167 // whole mesh.
168 // Off: gating on element quality also skips SURFACE vertices, whose smoothing is driven
169 // almost entirely by the envelope term (w_amips 1e-4), not by the quality of the elements
170 // around them. On 122839 the filtered run exhausted 60 iterations at max energy 21.03
171 // while the unfiltered one converged to 19.9998 in 54 -- and did so in LESS wall time
172 // (875s vs 947s), because needing fewer iterations more than paid for the extra vertices
173 // per pass.
174 bool skip_good_regions = false;
