Detailed Description

template<typename Elem, size_t InlineN, typename KeyOf>
class wmtk::detail::SmallSortedSet< Elem, InlineN, KeyOf >

A sorted set of elements with distinct keys, held inline up to InlineN and on the heap beyond: the storage behind LabelIds and LabelCounts.

Why not a bitset: a simplex lies on one input almost always and on two or three where inputs meet, whatever the number of inputs, so the record costs the same for one label as for thousands. Until 2026-11 the inputs were a 64-bit mask (InputSet), one bit per input, and a mesh with more than 64 labels was refused (scan_1, 78 cells).

Bytes, not a union with a pointer: the records stay aligned as Elem (2), not as a pointer (8). The heap block, when there is one, is new Elem[capacity] (at most 255 elements on one simplex) and its pointer is memcpy'd into the bytes. Copies are deep, so the attribute collections' copies and rollbacks need nothing else. Elem is trivially copyable; Key(e) gives its key.
