Detailed Description

A triangle complex and the edits it went through, in commit order.

Replaying the edits from the snapshot (Replay.hpp) reproduces every later state, ids included, which is what a map between the first and the last state is built from.

Member Data Documentation

◆ feature_edges

std::vector<std::array<uint64_t, 2> > wmtk::history::SurfaceHistory::feature_edges

Feature edges: curves the operations keep, which a map must take onto themselves (label boundaries, say). Each a vertex pair with the smaller id first. The edits carry them along by fixed rules – a split feature edge leaves two feature halves, a collapse renames the removed endpoint's feature edges to the survivor, a swap never takes one – so only the snapshot lists them.

◆ input_vertex_ids

std::vector<uint64_t> wmtk::history::SurfaceHistory::input_vertex_ids

The id the mesh the history starts from gives each vertex of the first state – for a history that starts at a tet mesh's tracked surface rather than at input files, so that a point on it is named by the mesh's three vertices, as output_vertex_ids names one on the last. Empty when the first state is the input files' triangles, as read.

◆ output_vertex_ids

std::vector<uint64_t> wmtk::history::SurfaceHistory::output_vertex_ids

The id the application's output gives each vertex of the last state, kNoVertex for one it does not write – for an application whose output numbers vertices its own way: a tet mesh's, whose tracked surface is no element of the output, so a point on it is named by the output's three vertices. Empty when the last state's ids are the output's own, as a TriMesh application's are.
