31 // Eleven bytes. The values are tiny -- a flag, a bbox side in [-1, 5], a class in {0, 1}, an
32 // orientation count that is +-1 or 0 almost everywhere, a 64-bit input set -- but as int the
33 // struct was 12 bytes, and the 3D meshes carry four of these per tet slot (the 2D ones three
34 // per triangle slot) in storage preallocated several times over: on the largest tetwild
35 // inputs that alone was most of a gigabyte. The class and the orientation share a byte as
36 // bitfields; both are int8_t so every compiler packs them together. The input set took it
37 // from 3 to 5 bytes, 8 more per tet slot: on Thingi10K 46024, the largest tetwild input of
38 // the challenging set (156k tets after insertion, two iterations), peak RSS went from 1006
39 // to 1017 MB (+1.1%), the simplification's per-face input id included. 64 bits rather than 16
40 // so that simwild can give every label its own bit -- each tet tag's region as well as each
41 // face tag -- and hold every surface face to its own labels' envelopes: segmented images
42 // carry more than 16 labels. That is 6 bytes more per face record: on the same
43 // 46024, one input, serial, peak RSS 1001 MB on main (3 bytes) and 1007 MB here (11 bytes).
44 // With WMTK_PER_INPUT_ORIENTATION 43 bytes: see m_input_orientation.

163 static int ascending_parity(const std::array<size_t, N>& v)
164 {
165 int inversions = 0;
166 for (size_t i = 0; i < N; ++i)
167 for (size_t j = i + 1; j < N; ++j)

169 return (inversions % 2 == 0) ? 1 : -1;
